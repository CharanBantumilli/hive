# Hive v1.0.11: MCP from the Terminal

> An agent can run an MCP server from the terminal instead of carrying its tools in every prompt,
> through Stephan Fitzpatrick's [mcp2cli](https://github.com/knowsuchagency/mcp2cli). `worker_llm`
> and each queen's own model take `extra_body`, and queens reflect on memory every few replies
> rather than after every model call.

## New

- **MCP servers agents run from the terminal.** An MCP server's tools load into every agent's tool
  list, and their schemas go with every model call: ComfyUI's official server,
  [comfy-mcp](https://github.com/Comfy-Org/comfy-mcp), has 39 tools, about 15,600 tokens. Register
  a server with `hive mcp add --as-cli`, switch one with `hive mcp mode <name> cli`, or click
  **Use from terminal** under Configuration → Skills → MCP Tools → MCP Servers, and its tools stay
  out of the tool list. Each queen and worker gets one line naming the server instead (about 110
  tokens for ComfyUI) and runs it with `terminal_exec`:

  ```bash
  hive mcp run comfy --list
  hive mcp run comfy run-workflow --help
  hive mcp run comfy run-workflow --workflow-path /abs/wf.json --wait
  ```

  In a test, a queen given only that line listed ComfyUI's commands, wrote a workflow, rendered the
  image on the local GPU and showed it in the chat. The commands come from
  [mcp2cli](https://github.com/knowsuchagency/mcp2cli) by Stephan Fitzpatrick
  ([@knowsuchagency](https://github.com/knowsuchagency)), MIT-licensed, which turns an MCP server's
  tools into a command-line interface at runtime. Hive reads the server's connection from its
  registry and hands it to mcp2cli, with env vars and headers passed through the environment, never
  on a command line. A CLI-mode server can use the stdio, SSE or standard MCP HTTP transport. See
  [configuration.md](../configuration.md#servers-agents-run-from-the-terminal).
- **`hive mcp add` takes `--env`, `--cwd`, and the server's command after `--`**, so a command
  whose arguments start with `-` (`-- uvx --from comfy-mcp comfy-mcp`) can be registered.
- **`extra_body` for `worker_llm` and each queen's own model.** Only the main model sent
  `extra_body` (fields added to every request body as they are). `worker_llm` and each `queen_llm`
  entry now send theirs too, and a running chat that switches to or from a queen's own model
  switches its `extra_body` with it. For DeepSeek, `{"reasoning_effort": "max"}` sets how hard it
  thinks and `{"thinking": {"type": "disabled"}}` turns thinking off. See
  [configuration.md](../configuration.md#fields-a-provider-takes-in-the-request-body).

## Changed

- **Queens reflect on memory every few replies, not after every model call.** Reflection counted
  every model call, tool calls included, so on a busy channel it outnumbered the queen's own calls
  about four to one. It now counts her replies: a short reflection every 6, and every 4th of those
  also tidies all her memory files. `memory_reflection.every_turns` and `long_every` set both, and
  `memory_reflection.model: "worker"` runs reflection (and her dated timeline) on `worker_llm`. See
  [configuration.md](../configuration.md#how-often-queens-write-memory).

## Fixed

- **MCP servers on another Python version, when Hive runs from a uv-made virtualenv on Windows.**
  The `python.exe` uv put in a virtualenv (from uv's
  [#17821](https://github.com/astral-sh/uv/pull/17821) until
  [#19199](https://github.com/astral-sh/uv/pull/19199)) set `PYTHONHOME` for the interpreter it
  started, and every process Hive started inherited it. A server that `uvx` runs on another Python
  version then loaded Hive's standard library and died at import (`SRE module mismatch`), which
  Hive reported as "Connection closed"; under a Windows service, every health check of comfy-mcp
  failed this way. `hive` now drops that `PYTHONHOME` when it starts. It recognises uv's by the
  marker uv sets beside it, so a `PYTHONHOME` you set yourself is kept.
- **Retired Claude model.** `claude-sonnet-4-20250514` was switched off on June 15. Hive's fallback
  Anthropic model and the Anthropic key check now use `claude-sonnet-5-5`.

## For code built on Hive

- `aden-hive` depends on [`mcp2cli`](https://pypi.org/project/mcp2cli/) (`>=3.8,<4`, MIT). Its own
  dependencies were already Hive's, so it adds one package.
- `POST /api/mcp/servers` takes `"mode": "tools" | "cli"`, `POST /api/mcp/servers/{name}/mode`
  switches it, and the server list reports each server's `mode`.
- `LiteLLMProvider.reconfigure()` takes `extra_body`.
- A program that embeds Hive without the `hive` command can drop uv's leaked `PYTHONHOME` itself
  with `framework.utils.python_env.drop_launcher_pythonhome(os.environ)`.

`aden-tools` is released at the same version. It hasn't changed, but the two packages pin each
other exactly.
